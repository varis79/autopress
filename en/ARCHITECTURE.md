# ARCHITECTURE — how Autopress is built (source of truth)

> A **short, exact description of what exists today** in `starter/`. This takes precedence over
> `BLUEPRINT-MEDIO-AUTONOMO.md` (which is historical material, not executable). If anything in the
> blueprint contradicts this or decisions D1-D4, **this wins**.

## What it is

A Python pipeline (stdlib + `feedparser` + `anthropic`) that turns RSS feeds into a weekly
edition, controls it, and publishes it as a **static site**. No database: state lives in Git
(`data/editions/`).

## Pipeline (stage → file)

```
ingest → classify → dedupe → select → compose → qa → editorial_gate → publish
```
- `scripts/ingest.py` — downloads feeds (timeout/UA/retries), anti-SSRF (no local files
  or private hosts), per-source diagnostics.
- `scripts/classify.py`, `dedupe.py`, `select_stories.py`, `pipeline_core.py` — deterministic
  core (classification, dedupe with memory, selection with scoring/quotas/mode).
- `scripts/compose.py` — LLM writing (provenance by `ref_id`, anti-injection);
  `compose_stub.py` is the fallback without a key.
- `scripts/qa.py` — QA by levels (blocking/review_required/warning); in `strict`, it requires
  independent sources.
- `scripts/editorial_gate.py` — D1 quality-gate: which edition can be indexed.
- `scripts/publish.py` — renders the site from `data/editions/` (Git as the DB).
- `scripts/pipeline.py` — orchestrates everything; validates the config; prints JSON status.

## Config

- `config.json` (the operator's) validated against `autopress.schema.json`
  (`additionalProperties:false`). **Invalid config = it does not run** (exit 2).
- `fixtures/config.json` is ONLY for tests/demo. The production taxonomy is generated by the
  operator (`scripts/setup.py` assistant); a config with `meta.needs_taxonomy` does not publish.

## State machine (publishing and indexing)

Every persisted edition carries a `status`:
- `needs_review` → **noindex**, out of the sitemap (draft).
- `approved` → indexable in production.

Rules:
- `risk_profile=auto` + quality-gate OK + no-stub → `approved`.
- `review`/`strict` → `needs_review`; a human moves it to `approved` with `scripts/approve.py`.
- **stub is never published in production** (invariant). The **sitemap only lists approved**.

## Guardrails (enforced by code)

Unsupported figures → block; provenance by `ref_id` (no invented sources); URLs only
http/https; anti-injection (escaping of `<`/`>`); `noindex` by default. Details in
`07-GUARDARRAILES.md`.

## Deploy

Static output in `site/`; the host serves it (see `04-DESPLIEGUE.md`). Weekly CI in
`../.github/workflows/publish.yml` (auto→publishes, review/strict→PR).

## For the agent: what to edit and what not

- **Edit**: `config.json`, `prompts/master-prompt.md`, `.env`, and the sources (`sources`).
- **Do not rewrite** the pipeline architecture or the schema without reason. Extend, don't
  reinvent.
- **Commands**: `python -m scripts.doctor` · `scripts.setup` · `scripts.serve` ·
  `scripts.pipeline [--config … --production]` · `scripts.approve <slug>` · `scripts.settings`.
- **Done criteria**: `python -m unittest discover tests` green and `doctor` OK.
